# 笔记 03 —— 数电基础①：进制与补码

> 对应清单 W1 · 10.08 条目。看似是"本科数电复习"，但这几页直接决定你后面写 Verilog
> 会不会踩"位宽截断""有符号数算错""溢出没判断"这一类坑。

## 为什么 FPGA 工程师要先把补码搞透

| 场景 | 不理解的后果 |
| --- | --- |
| 写 `reg [7:0] a = -1;` | 不知道里面其实存的是 `8'hFF`，后面做比较/移位全错 |
| 两个 8 位数相加 | 不做符号扩展就丢进位，滤波器累加溢出、结果反号 |
| 用有符号数做 FIR / 混频 | 乘法结果位宽算错，波形看起来"莫名其妙地跳变" |
| 跨模块传数据 | 一端 signed 一端 unsigned，仿真对了上板错 |
| 面试 | "补码为什么能表示 -128 而不能表示 +128" 是高频题 |

## 一、进制转换

- **二 → 十**：按权展开。`10110110₂ = 128+32+16+4+2 = 182`
- **十 → 二**：除 2 取余，倒序排列；或先拆成 2 的幂之和（更快）
- **二 ↔ 十六**：**4 位一组**直接替换，这是最常用的一组，要练到不用想
  ```
  0x2A5 = 0010 1010 0101
  ```
- **十 → 十六**：先转二进制再 4 位分组，比除 16 取余不容易错

> 记住 0~15 的二进制：`0=0000 1=0001 2=0010 3=0011 4=0100 5=0101 6=0110 7=0111`
> `8=1000 9=1001 A=1010 B=1011 C=1100 D=1101 E=1110 F=1111`

## 二、原码 / 反码 / 补码

以 8 位为例：

| 表示法 | +35 | −35 | 问题 |
| --- | --- | --- | --- |
| 原码（符号位 + 绝对值） | `0010 0011` | `1010 0011` | 有 `+0`(`00000000`) 和 `−0`(`10000000`) 两个零；加减要判符号 |
| 反码（负数 = 原码除符号位取反） | `0010 0011` | `1101 1100` | 仍然有两个零；运算要循环进位 |
| **补码（反码 + 1）** | `0010 0011` | `1101 1101` | ✅ 零唯一、加减统一、符号位可直接参与运算 |

**补码求法（两条路，都要会）**

1. 取反加一：`35 = 00100011` → 取反 `11011100` → `+1` → `11011101 = 0xDD`
2. 模运算：`256 − 35 = 221 = 0xDD`（更快，更适合口算）

**补码 → 真值**：看最高位。`0xB6 = 182`，最高位为 1 → `182 − 256 = −74`

## 三、补码真正解决的三件事

1. **减法变加法**：`A − B = A + (−B)`，硬件只需一套加法器
2. **0 唯一**：没有 `−0`，8 位就多出一个编码给 `−128`
3. **符号位直接参与运算**：不需要额外判断电路

**N 位补码的表示范围**：`−2^(N−1)` ~ `+2^(N−1) − 1`

| 位宽 | 范围 | 备注 |
| --- | --- | --- |
| 4 位 | −8 ~ +7 | |
| 8 位 | −128 ~ +127 | 最常用 |
| 16 位 | −32768 ~ +32767 | 音频 / ADC 数据常用 |
| N 位 | −2^(N−1) ~ 2^(N−1)−1 | |

## 四、溢出判断（必考，也是最容易写错代码的地方）

**规则**：只有当**两个同号数相加**时才可能溢出，结果符号与操作数相反即为溢出。

- 两正数相加得到负数 → 溢出
- 两负数相加得到正数 → 溢出
- 一正一负相加 → **永远不会溢出**

**例子（8 位）**

```
100 + 50 = 150      → 超出 +127
0x64 + 0x32 = 0x96  → 0x96 按补码解释 = -106   ← 正数+正数=负数，溢出

-100 + (-50) = -150 → 低于 -128
0x9C + 0xCE = 0x6A  → 0x6A = +106              ← 负数+负数=正数，溢出

60 + (-70) = -10
-70 = 256-70 = 186 = 0xBA
0x3C + 0xBA = 0xF6  → -10                       ← 异号相加，正确且不溢出
```

**硬件层面的判据**：`溢出 = (最高位进位) XOR (次高位进位)`

> 写代码时的对策：**先扩位再运算**。
> 两个 8 位有符号数相加，至少用 9 位（通常直接给 16 位）存结果，最后再按需截位。

## 五、符号扩展 / 零扩展

| 操作 | 对象 | 8 位 → 16 位 | 说明 |
| --- | --- | --- | --- |
| **符号扩展** | 有符号数 | `0x8F (−113) → 0xFF8F` | 高位补**符号位**，值不变 |
| **零扩展** | 无符号数 | `0x8F (143) → 0x008F` | 高位补 `0`，值不变 |

> 搞混了就会出现"明明是负数，一扩展变成正数"——这是新手最常见的 bug 之一。

## 六、与 Verilog 的对应关系（重点）

```verilog
reg        [7:0] a;          // 默认 unsigned，范围 0~255
reg signed [7:0] b;          // 显式有符号，范围 -128~127

a = -8'd1;                   // 实际存进去是 8'hFF
b = -8'd1;                   // 同样是 8'hFF，但后续运算按有符号解释

$signed(a)                   // 临时把无符号数当有符号用
```

**算术右移 vs 逻辑右移**

- `>>`（逻辑右移）：高位补 0 → 无符号数除法
- `>>>`（算术右移）：高位补符号位 → 有符号数除法，负数才不会变成正数

```
0xE8 (-24) >>  1 = 0x74 (+116)   ← 逻辑右移，负数被"扭"成正数，错了
0xE8 (-24) >>> 1 = 0xF4 (-12)    ← 算术右移，正确
```

## 七、易错点清单

1. **补码的负数范围比正数多一个**：8 位是 −128 而不是 −127，`−128` 的补码是 `0x80`，对它取负还是它自己（溢出）
2. **位宽截断**：`8'hFF + 8'h01 = 9'h100`，但赋给 8 位变量就变成 `8'h00`
3. **比较运算**：`reg [7:0]` 无符号比较时 `0xFF(255) > 0x01`，有符号比较时 `0xFF(-1) < 0x01`
4. **乘法位宽**：N 位 × M 位 = N+M 位，别直接赋回 N 位
5. **`$signed` 只对表达式生效**，不改变变量本身的声明
