# 参考答案

## 一、进制转换

| 题 | 答案 | 过程 |
| --- | --- | --- |
| 1 | **182** | `128+32+16+4+2` |
| 2 | **1015** | `3×256 + 15×16 + 7 = 768+240+7` |
| 3 | **11011001** | `128+64+16+8+1` |
| 4 | **0x3E8** | `3×256=768`，余 232；`14×16=224`，余 8 |
| 5 | **0010 1010 0101** | 每位十六进制直接拆 4 位二进制 |

## 二、原码 / 反码 / 补码

| 题 | 答案 |
| --- | --- |
| 6 | 原码 `0xA3`(`10100011`)；反码 `0xDC`(`11011100`)；补码 `0xDD`(`11011101`) |
| 7 | `0xFF` |
| 8 | `0x80`。**原因**：8 位共 256 个编码，0 只占一个（`00000000`），剩下 255 个非零编码分给正负两半时分不匀，负数多拿一个 → 范围变成 `−128 ~ +127`。`+128` 想用 `0x80`，但 `0x80` 的最高位为 1，在补码规则下已被定义为 `−128`，所以表示不了 |
| 9 | **−74**（`0xB6 = 182`，最高位为 1 → `182 − 256 = −74`） |
| 10 | `0x7F = **+127**`；`0x80 = **−128**` |

## 三、补码运算与溢出

| 题 | 答案 | 溢出？ |
| --- | --- | --- |
| 11 | `0x64 + 0x32 = **0x96**`，按补码解释 = `150 − 256 = −106` | **溢出**（两正相加得负；真值 150 > +127） |
| 12 | `0x9C + 0xCE = 0x16A` → 截 8 位 = **`0x6A`** = +106 | **溢出**（两负相加得正；真值 −150 < −128） |
| 13 | `−70 = 0xBA`；`0x3C + 0xBA = **0xF6**` = −10 | **不溢出**（异号相加永不溢出） |
| 14 | `0x5A + 0x3C = **0x96**` = −106 | **溢出**（90 + 60 = 150 > +127） |
| 15 | ① **行为判据**：两正数相加得负数，或两负数相加得正数 → 溢出；异号相加永不溢出<br>② **硬件判据**：`溢出 = 最高位进位 ⊕ 次高位进位`（为 1 即溢出） |

## 四、位宽、符号扩展与 Verilog

| 题 | 答案 |
| --- | --- |
| 16 | **`0xFF8F`**（高位补符号位 1，真值仍是 −113） |
| 17 | **`0x008F`**（高位补 0，真值仍是 143） |
| 18 | **`0xFF`**（`−8'd1` 的补码就是全 1） |
| 19 | `0xE8` 真值 = `232 − 256 = −24`<br>逻辑右移 `>>1` = **`0x74`** = +116（负数被"扭"正，错误）<br>算术右移 `>>>1` = **`0xF4`** = −12（正确） |
| 20 | 4 位：`−8 ~ +7`<br>8 位：`−128 ~ +127`<br>16 位：`−32768 ~ +32767`<br>N 位：`−2^(N−1) ~ +2^(N−1) − 1` |
